## 如何理解这些记录

覆盖2026年10月13日至11月13日的91份物理会话文件，其中72份非空会话纳入审计，19份空会话排除。会话数量不等于独立任务数量。

607条记录包含：285条已确认问题、46条候选问题、142条证据缺口、134条正例与判断边界；不是607个已确认故障，也不是607个独立事件。120个主题仅用于检索，不代表120个根因或优先级。原始编号、分类及各轮记录保留，后续原因解释作为补充，可能纠正旧解释。

原记录可能混合正常产品迭代、必要适配、执行失误与证据不足。应结合原因补充和当时用户要求阅读，不能把所有反复修改都计作低效。耗时记录、合理估算和无法确认的等待应分别对待；这些材料不证明任何固定的提速比例。

## 目录关系

- 根目录的 terra、sol_dev、sol_env、root_reuse：72份最初审计报告。
- issue_descriptions：逐条展开的问题、可能方案、检索分类及逐份覆盖核验。
- cause_annotations：在原编号下补充聊天背景、原因证据、必要成本与可避免成本。
- PROPOSED_SOLUTION_DESIGN.md：系统级解决方案设计与协作模式建议；不覆盖原始 finding。
- agent-workbench/：独立的 Codex CLI 工作流安装工具；其运行机制、测试和使用说明见子目录，不改变历史审计数据。

记录中的“第N行”指本地原始会话快照的物理行；仓库保留定位信息，但不包含完整原始会话，因此不是仅凭公开仓库即可独立复现的原始证据集。源审计哈希对应脱敏前本地基线，不能作为公开文件的内容哈希。

## 历史审计数据公开范围

审计数据仅上传审计报告和索引的脱敏副本。未上传原始JSONL会话、历史数据库、完整模型输入输出及工具返回、附件或凭据。私人目录、邮箱、服务地址及可识别凭据按规则替换为可见占位符。脱敏不改变问题编号及分类；原始文件留在本地且未改写。
